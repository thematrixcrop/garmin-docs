# 设计工作流和交互

建立信息架构后，就可以将其转换为工作流。

## 分层导航

传统 Garmin 用户界面采用分层结构，视图会根据用户的选择逐层堆叠。每台设备都有导航和退出层级的标准行为，但不同产品的标准行为可能不同。

尽量限制导航层级的深度。应优先让用户快速选择，避免迫使用户做出多次选择。

## 行为

以下抽象行为适用于所有 Garmin 设备。

| 行为 | 说明 |
| --- | --- |
| 选择（Select） | 从一组项目中选择项目。 |
| 开始/停止（Start/Stop） | 标记开始或结束的操作。在按钮设备上，这通常与选择（Select）相同。 |
| 下一个/上一个（Next/Previous） | 选择下一个或上一个项目，或在页面循环中导航到下一页或上一页。在按钮设备上，这通常对应上/下按钮。 |
| 返回（Back） | 退出应用屏幕或视图，返回上一个屏幕或视图。 |
| 菜单（Menu） | 打开应用设置菜单。 |

## 常见模式

将信息架构转换为工作流时，可以利用 Garmin 设备上的以下模式：

### 页面循环

页面循环是一组视图组成的轮播。用户处于页面循环中时，界面会展示一组信息页面，为用户提供不同的数据和洞察。下一页和上一页都有标准行为，越过最后一页通常会回到第一页。

![页面循环](/connect-iq/resources/ux-guide/page-loops.png)

### 对话框

对话框通常是包含消息的模态屏幕，用户必须确认已阅读后才能继续。它们可用于错误消息、说明或其他指导。

![对话框](/connect-iq/resources/ux-guide/dialogs.png)

### 进度条

进度条告诉用户需要等待异步操作完成。进度条有两种样式：从 0% 计数到 100% 的标准进度条，以及无法量化完成时间时使用的忙碌进度条。

![进度条](/connect-iq/resources/ux-guide/progress-bars.png)

### 确认

确认页面用于确认用户操作，既可以确认用户的决定，也可以在用户退出流程时增加一道确认步骤。

![确认](/connect-iq/resources/ux-guide/confirmations.png)

### 选择菜单

选择菜单允许用户在两个或多个项目之间进行选择。项目以一维列表呈现，也可以选择显示图标。

![选择菜单](/connect-iq/resources/ux-guide/selection-menu.png)

### 设置菜单

设置菜单通常可以通过菜单（Menu）行为从应用基础视图打开，用于修改应用的全局设置。

![设置菜单](/connect-iq/resources/ux-guide/settings-menu.png)

## 交互

规划工作流时，不可避免会遇到无法通过常见 UI 模式解决的决策。此时需要考虑让用户在设备上做出决定的最佳方式。

Garmin 在设计产品时会考虑这种使用场景，其中一个关键因素是产品使用触摸屏还是按钮。主要面向移动设备开发的开发者可能不熟悉实体按钮。触摸屏在室内环境中使用良好，但戴手套、屏幕潮湿或身体处于运动状态时可能难以操作。在这些场景中，按钮提供的触觉反馈可以带来更好的体验。

Connect IQ 允许针对触摸屏和按钮设备提供不同的定制体验，也提供了让同一份实现同时支持两者的工具。最终应由您决定是否根据不同输入模式调整应用的交互模型。

### 输入模式

以下是 Garmin 设备常见的输入模式：

![](/connect-iq/resources/ux-guide/five-button.png)

**五按钮**配置在左侧有三个按钮，右侧有两个按钮，各按钮行为如下：

-   左上：按下切换背光；按住打开 Controls（控制）菜单。

-   左中：按下执行上一项或向上操作；按住执行菜单（Menu）操作。

-   左下：按下执行下一项或向下操作。

-   右上：按下执行选择（Select）操作，通常用于 Garmin 活动的开始/停止（Start/Stop）操作。

-   右下：按下执行返回（Back）操作。


![](/connect-iq/resources/ux-guide/touchscreen-two-button.png)

**触摸屏双按钮**配置将触摸屏与两个导航按钮结合起来：

-   顶部按钮用于 Start/Stop；按住打开 Controls 菜单。

-   底部按钮执行 Back 操作；按住执行 Menu 操作。


以下操作同样是标准行为：

-   向上滑动执行上一项或向上操作。

-   向下滑动执行下一项或向下操作。

-   可以在触摸屏上拖动和快速滑动菜单。

-   点击屏幕项目执行 Select 操作。

-   从右向左滑动执行 Back 操作。


![](/connect-iq/resources/ux-guide/edge-touchscreen-one-button.png)

**触摸屏单按钮 Edge** 配置将触摸屏与电源按钮结合起来，所有交互都通过触摸屏完成：

-   从左向右滑动执行上一项或向上操作。

-   从右向左滑动执行下一项或向下操作。

-   可以在触摸屏上拖动和快速滑动菜单。

-   点击屏幕项目执行 Select 操作。

-   点击屏幕上的 Back 按钮执行 Back 操作。

-   点击屏幕上的汉堡菜单执行 Menu 操作。

### 移动应用设置

![](/connect-iq/resources/ux-guide/mobile-app-settings.png)

Connect IQ 允许开发者提供一组可配置的应用设置，用户可以在 Garmin Connect™ Mobile 应用、Connect IQ™ Mobile 应用或 Garmin Express 中编辑这些设置。

设置可以包含标签和提示，值可以是以下任一类型：

-   布尔值（Boolean）

-   数值（Number）

-   文本（Text）

-   电话号码（Phone）

-   电子邮件（Email）

-   URL

-   日期（Date）

-   密码（Password）


应用设置可以在不增加复杂设备端 UI 的情况下，让应用更易配置。当用户在移动端更改设置时，Connect IQ 应用可以收到通知并立即反馈。

## 移动端身份验证

云服务通常要求用户使用用户名和密码进行身份验证。在移动设备上，这类流程很容易完成；但 Garmin 设备的输入能力有限，输入凭据可能很困难。

Connect IQ 提供了标准身份验证方法，可以将身份验证交给移动设备。应用可以选择将身份验证交给 Garmin Connect Mobile 应用，或者在 System 5 中交给 Connect IQ Store Mobile 应用。此机制要求云服务通过 Web 浏览器视图支持 OAUTH2 身份验证。

需要用户进行身份验证时，应显示对话框，指导用户在手机上打开相应应用。如果用户在手机上启用了该应用的通知，还会收到移动通知。打开移动应用后，用户会被提示在手机上开始身份验证。

![](/connect-iq/resources/ux-guide/mobile-authentication.png)

凭据输入完成后，Web 视图会关闭，凭据会发送到 Connect IQ 应用。此时，Connect IQ 应用应继续执行工作流。

## 最佳实践

定义应用交互时，可以遵循以下最佳实践：

-   将输入降到最低。Garmin 设备向用户提供大量信息，这些信息应在三到四次设备交互内完成访问。用户与应用交互越多，就越难专注于手头的任务。

-   使用上下方向的页面循环，而不是左右方向，以便在按钮和触摸屏设备上都获得良好体验。水平页面循环不适合按钮配置。

-   如果要在触摸屏应用中使用屏幕按钮，请确保按钮行为直观且明显。

-   如果应用用于身体活动，请尽量减少交互次数，让用户专注于活动而不是应用。

-   谨慎在设备上使用文本输入。可以改用移动应用设置，或生成有用的默认字符串，让用户之后在移动端或 Web 上修改。

-   使用原生菜单、确认页面和进度条。它们会自动呈现产品个性，用户也已经熟悉这些交互方式。

-   返回（Back）是 Garmin 设备上最常见的行为之一，避免在应用中修改它。

-   不要要求用户先完成移动应用设置才能使用应用。应用应无需用户进入设置流程即可使用。

-   不要依赖移动通知完成身份验证流程。始终在 Connect IQ 应用中清晰指导用户打开适当的移动应用或网站。
